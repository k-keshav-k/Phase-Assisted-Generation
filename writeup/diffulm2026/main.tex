\begin{abstract}
Diffusion language models can revise several tokens per forward call, but their practical efficiency depends on deciding how large a span to attempt and when to stop refining it. Phase-Adaptive Generation (PAG) learns this refinement budget from prior block trajectories while retaining reactive delimiter boundaries. On LLaDA-8B-Instruct, PAG uses 6.7\% fewer model calls on MATH-500 while accuracy is 1.33 percentage points lower; on GSM8K it saves 4.0\% while accuracy is 1.60 percentage points lower. PAG obtains this trade-off by separating two decisions: recent blocks predict how much refinement to spend next, while current predictions still choose where the block ends. We then test how far this gain can be extended. After normalizing each model--dataset setting to its AdaBlock baseline, a rule shared by LLaDA and Dream uses 9.6\% fewer calls overall, although Dream does not meet our accuracy requirement. Stricter rules preserve outputs and save up to 1.24\%. Batched checking suggests still larger call reductions, with exact matching unresolved in 22 of 64 pilot prompts. Overall, phase history is a useful signal for allocating compute; current boundaries and reference checks provide the safeguards needed to use it reliably.
\end{abstract}

\section{Introduction}
\label{sec:introduction}

Diffusion language models generate by repeatedly revising masked positions, so one model call can advance several tokens at once. This parallelism creates a control problem absent from left-to-right decoding: how large a span should the model attempt, and how long should it refine that span before moving on? Existing decoders answer with fixed schedules or current-step confidence signals~\citep{wu2025fastdllm,lu2026adablock,mohamed2025sched}. Both are useful, but neither asks whether the trajectory itself forecasts where later compute will be needed.

Phase-adaptive generation (\pag{}) starts from a simple observation: reasoning traces are not uniformly difficult. Template text and delimiters often stabilize early, while arithmetic, variable binding, and answer finalization remain uncertain for longer. The difficult part is turning this structure into a decoder. Offline accuracy is not enough. The scheduler changes the trajectory that produces its own future features; block sizes are strongly multimodal; and a premature commitment can alter every later block. A useful predictor can therefore be a poor controller.

We develop the method from trace analysis through deployment. We first instrument Dream and LLaDA~\citep{ye2025dream,nie2025llada}, measure when tokens stop changing, and use change-point detection (CPD) to find local shifts in uncertainty. Because the detected boundaries vary with the detector settings, we train instead on 138{,}901 block records collected by running AdaBlock on 5{,}000 GSM8K training problems. During generation, PAG records each completed block's size, confidence, and number of model calls. A small Transformer reads the latest eight block records and predicts how many refinement calls to allow for the next block. If recent blocks have stabilized quickly, it can assign a smaller budget; if they have needed more refinement, it retains more calls. AdaBlock still decides where the next block ends from the model's current predictions. The later evaluations test whether this design transfers across models, preserves outputs under stricter rules, and benefits from batched checking.

Across the experiments, counting every proposal and refinement call shows that \pag{} reduces the mean number of forward evaluations (\nfe{}) on LLaDA by 4.0\% on GSM8K and 6.7\% on MATH-500, with accuracy decreases of 1.60 and 1.33 percentage points. The gain comes from splitting the scheduling decision in two. AdaBlock still uses the model's current predictions to decide where each block ends. PAG changes only how many refinement calls the next block receives, using the last eight completed blocks as context. Predictable stretches can therefore stop earlier without letting the history model change the span being decoded. The later runs test how safely the gain extends: after dividing each setting by its AdaBlock baseline, the cross-model rule reduces \nfe{} by 9.6\% overall; output-preserving variants save up to 1.24\%, and batched checking produces larger raw reductions. The main result is a clear efficiency--quality trade-off on LLaDA, together with direct evidence about the safeguards needed to extend it.

\paragraph{Contributions.}
We make three contributions. First, we introduce \pag{}, a hybrid diffusion-LM scheduler that uses the last eight completed blocks to set the next refinement budget while leaving AdaBlock in control of block boundaries. When every model call is counted, \pag{} reduces LLaDA \nfe{} by 4.0\% on GSM8K and 6.7\% on MATH-500, with accuracy decreases of 1.60 and 1.33 percentage points. Second, we connect token-stabilization analysis and 138{,}901 block records to a practical scheduler in which recent refinement behavior changes the next budget. A size-conditioned control separates this history signal from information already available in the current block. Third, seven artifact-backed protocols across LLaDA and Dream test how far the mechanism extends through cross-model transfer, exact output preservation, and batched verification. They lead to a concrete design rule: use current predictions for block boundaries, history for bounded budget adjustments, and an audited reference transition for token acceptance.

\section{Related work}
\label{sec:related}

\paragraph{Masked and block diffusion language models.}
Discrete and masked diffusion models replace left-to-right factorization with iterative denoising~\citep{lou2024sedd,sahoo2024mdlm}. LLaDA and Dream scale this formulation to instruction following and reasoning~\citep{nie2025llada,ye2025dream}. Block diffusion introduces a semi-autoregressive interface: the decoder completes one contiguous block before exposing it as context to the next~\citep{arriola2025block}. That interface makes block size and within-block refinement explicit controls. Our work studies whether realized block histories help set those controls; it does not change the model or training objective.

\paragraph{Adaptive and early-exit decoding.}
Fast-dLLM combines confidence transfer with key--value (KV) caching and parallel decoding~\citep{wu2025fastdllm}. AdaBlock chooses semantic boundaries from delimiter confidence and adapts refinement to the active block~\citep{lu2026adablock}; it is our native decoder and strongest same-stack baseline. Adaptive Parallel Decoding (APD) learns token-wise denoising paths, whereas SchED and more recent stability rules stop from inter-step similarity or persistent predictions~\citep{israel2025apd,mohamed2025sched,mohamed2026less}. These methods establish that current-state confidence and stability are useful. \pag{} asks a different question: whether previous blocks add predictive value after controlling for a strong current-state or size-conditioned rule.

\paragraph{Risk control and verified acceleration.}
Learn-then-Test and conformal risk control provide finite-sample tools for selecting a policy under a bounded loss~\citep{angelopoulos2021ltt,angelopoulos2022crc}. We apply this machinery to a binary loss that records whether early stopping changes a block relative to full refinement; task correctness is evaluated separately. Self-speculative diffusion-LM decoders instead batch draft states and verify them against a reference transition~\citep{gao2025ssd,han2026s2d2}. Our later protocols combine these ideas but also audit a systems assumption that is easy to omit: a nominally deterministic transition must remain invariant when evaluated alone or as one row of a batch. What remains unclear in this literature is whether a predictive phase signal survives both closed-loop deployment and the batch implementation of verification. Our contribution is the resulting end-to-end evidence boundary, not a claim of superiority over these contemporaneous decoders.

\section{Phase-adaptive generation}
\label{sec:method}

\pag{} has three stages (Figure~\ref{fig:pipeline}). First, offline trace analysis tests whether different parts of a response need different amounts of refinement. Second, completed AdaBlock runs train a predictor for the next block's call budget. Third, during generation, PAG records the size, confidence, and call count of each completed block and feeds the latest eight records to the predictor. Recent blocks that stabilized quickly lead to a smaller budget; blocks that needed more refinement lead to a larger one. AdaBlock continues to choose the block boundary from the model's current predictions. This is how PAG cuts model calls without allowing the history predictor to choose the generated span, and the division of responsibilities was fixed before the audited evaluation.

\subsection{Phase signals are diagnostic, not labels}
\label{sec:phase-signals}

For each output position, we record its predicted identity, top-one and top-two probabilities, and entropy after every refinement call. The stabilization time of token $i$ is the earliest step after which its identity never changes,
\begin{equation}
  s_i=\min\{t : \hat{x}_i^{(u)}=\hat{x}_i^{(T)}\ \text{for all }u\ge t\}.
  \label{eq:stabilization}
\end{equation}
We read confidence, margin, entropy, and step index at the stabilization time in Equation~\ref{eq:stabilization}, then segment each feature along token position with Pruned Exact Linear Time (PELT)~\citep{killick2012optimal}. Figure~\ref{fig:phase-data} shows the recurring pattern: long high-confidence spans are interrupted by lower-confidence computation, and block sizes concentrate on delimiter-only and default-cap modes.

The segmentation is intentionally not used as supervision. Boundaries move when the feature, smoothing window, cost, or penalty changes; representative traces yield between two and eight segments under reasonable settings. CPD therefore establishes that trajectories are structured, but does not define a stable scheduler target. The training path instead uses decisions directly observed from a block decoder.

\subsection{Block-native next-control prediction}
\label{sec:predictor}

We run AdaBlock with LLaDA-8B-Instruct on 5{,}000 GSM8K training problems~\citep{cobbe2021gsm8k}. After each decoded block, we store its size and realized \nfe{}, stabilization/refinement statistics, mean and minimum confidence, digit fraction, delimiter fraction, and gap statistics. The corpus contains 138{,}901 training tuples and 5{,}543 validation tuples. Sliding windows of eight realized tuples predict the next pair $y_t=(b_t,r_t)$, where $b_t$ is block size and $r_t$ is the refinement budget.

The target distribution rules out ordinary regression. A squared-error predictor averages the size-1 delimiter mode and the content-block mode, producing boundaries that seldom occur in the trace corpus. We instead use a Transformer encoder~\citep{vaswani2017attention} with a 128-way categorical head for $b_t$ and an 83-threshold ordinal head for $r_t$. The budget head is conditioned on the block-size logits. With categorical logits $z^b$ and ordinal logits $z^r$, training minimizes
\begin{equation}
 \mathcal{L}=\operatorname{CE}(z^b,b_t)
 +\frac{1}{83}\sum_{k=1}^{83}\operatorname{BCEWithLogits}
       \bigl(z^r_k,\mathbf{1}[r_t>k]\bigr).
 \label{eq:loss}
\end{equation}
Here, CE is categorical cross-entropy, and BCEWithLogits is binary cross-entropy applied to logits. The model has hidden size 64, four heads, four layers, 0.1 dropout, and learning rate $5\times10^{-4}$. Inputs are standardized with the training-set mean and standard deviation. Appendix~\ref{app:predictors} reports regression, random-forest, and architecture ablations.

\subsection{Hybrid online scheduling}
\label{sec:scheduler}

At block $t$, AdaBlock scans the model's current token probabilities for a high-confidence delimiter and returns the boundary $b_t$. The first block follows AdaBlock; later blocks pass the last eight realized tuples to the predictor and use only its budget $r_t$. Within the active block, masked positions are refined until the budget is reached. The decoder may then exit when all remaining predictions exceed confidence 0.8 or have stayed unchanged for two calls; a hard ceiling prevents unbounded refinement. Each initial proposal call and each refinement call counts toward \nfe{}.

Letting the predictor choose both controls often selects $(b_t,r_t)=(1,1)$. This trivial tuple then encourages another small prediction, causing the online features to drift from the training data. Retaining AdaBlock's delimiter boundary breaks the feedback loop and isolates the experimental question: how does history-conditioned budgeting compare with AdaBlock and a control conditioned only on the current block size $b_t$?

\section{Evidence protocol}
\label{sec:protocol}

\paragraph{Initial audited evaluation.}
The primary \pag{} comparison uses deterministic LLaDA-8B-Instruct decoding on all 1{,}319 GSM8K test problems and a 300-example index-stratified MATH-500 sample~\citep{hendrycks2021math}. GSM8K also includes a frozen development slice for choosing among eight scheduler variants and a disjoint 919-example confirmatory complement. The comparators are AdaBlock and a history-free lookup policy that returns the median training \nfe{} for the current block size. Every method counts the boundary proposal call and all subsequent refinement calls. The legacy course counter omitted the initial proposal, so those earlier values are excluded from every claim here.

\paragraph{Cross-model evaluation.}
To test whether the stopping rule transfers across model families, we add a risk check and call the resulting policy risk-calibrated \pag{} (\rcpag{}). At each possible stop, a small predictor estimates whether committing the current block would differ from continuing the same decoder state to full refinement. \rcpag{} stops only when this risk is below a calibrated threshold; otherwise, it continues refining. We use fixed LLaDA-8B-Instruct and Dream-v0-Instruct-7B checkpoints, temperature zero, generation length 256, at most 64 refinement calls, and block length at most 64.

Separate mixtures of GSM8K, MATH, and Mostly Basic Python Problems (MBPP) training data are used to train the risk predictor, choose among stopping rules, and calibrate the selected rule~\citep{austin2021mbpp}. Confirmation uses 500 GSM8K test, 300 MATH-500, 100 sanitized MBPP, and 100 HumanEval prompts~\citep{chen2021humaneval}; HumanEval is outside the calibration domain. During calibration, each proposed stop is paired with a reference continuation that starts from the same decoder state and runs to full refinement. The prompt-level loss is one if any early-committed block differs from its reference and zero otherwise. Exact binomial Learn-then-Test selects among the candidate rules while limiting the probability of any false selection across the family to 0.05. This statistical guarantee bounds the declared disagreement loss, not answer correctness.

\paragraph{Criteria for a confirmed result.}
Results are paired by prompt. We report mean \nfe{}, exact task accuracy, and latency, with 10{,}000-sample paired bootstrap intervals where available. Accuracy differences are absolute percentage-point changes: moving from 38\% to 37\%, for example, is a decrease of one percentage point. A cross-model policy counts as a confirmed extension only if it reduces \nfe{} on both models, beats the best eligible rule that does not use learned history, and has an accuracy-difference lower bound of at least $-2$ percentage points. Later protocols also require a minimum saving on each model or exact agreement with the reference output. For batched protocols, one batched forward call counts as one physical \nfe{}; the number of rows evaluated within that call is reported separately.

\subsection{PAG saves up to 6.7\% NFE by adapting refinement budgets}

Table~\ref{tab:initial-results} gives the LLaDA result. Relative to AdaBlock, \pag{} saves 4.0\% \nfe{} on GSM8K and 6.7\% on MATH-500, while accuracy is 1.60 and 1.33 percentage points lower. On the untouched GSM8K complement, the paired accuracy difference is $-1.20$ percentage points, with a 95\% confidence interval of $[-2.61,0.22]$ percentage points. This is the paper's main efficiency--quality result: history-conditioned budgets consistently reduce calls on both reasoning benchmarks.

\subsection{Cross-model calibration separates transferable and model-specific gains}

The cross-model experiment showed that phase history remained predictive beyond the original scheduler. All candidate stopping rules chosen before calibration also passed their finite-sample tests for full-refinement disagreement. To compare settings with different baseline costs, we divide each policy's \nfe{} by AdaBlock's \nfe{} on the same model--dataset pair and average the four ratios. This normalized \nfe{} falls from 1.000 to 0.904, compared with 0.968 for the best eligible rule without learned history. On LLaDA, the policy preserves GSM8K accuracy and lowers MATH-500 accuracy by only 0.4 percentage points while saving 2.1\% and 1.3\% \nfe{}. Dream provides larger call reductions, but its accuracy changes exceed the predeclared limit; the lowest lower endpoint among the accuracy confidence intervals is $-21.2$ percentage points, so the joint policy does not qualify as a confirmed cross-model extension. The experiment therefore separates a conservative transferable gain on LLaDA from an aggressive, model-specific Dream setting.

\subsection{Conservative routing preserves outputs}

The next four protocols prioritize exact output preservation. A local risk-threshold policy stops only when the current block's predicted risk falls below a threshold; it saves 9.1\%/3.2\% \nfe{} on LLaDA/Dream, but Dream falls below the predeclared 5\% savings floor. A benefit-and-harm policy adds predictors for both the expected saving and the chance of changing the answer. Its harm AUROC is 0.372/0.456, which is too low to use this decision rule. A prompt-level policy instead limits the cumulative predicted risk and number of early stops over an entire prompt; a relaxed version allows larger limits. On the held-out sets used to choose candidates, these prompt-level policies record zero harmful regressions while saving 0.75\%/0.45\% and 1.24\%/0.65\%. These runs establish that the learned signal can preserve observed outputs, with a smaller gain than the main PAG setting.

\subsection{Batched verification points to larger call reductions}

The batched-reference pilot checked several fixed numbers of future refinement steps together in one model call. This lowered physical invocations from 83.47 to 71.19 on LLaDA and from 97.63 to 76.81 on Dream, reductions of 14.7\% and 21.3\%. These were the largest raw call reductions in the progression and showed the potential of moving several checks into one invocation. The implementation was not lossless: 22 of 64 prompt trajectories disagreed with AdaBlock, and LLaDA latency rose from 3.09 to 3.83 seconds because each invocation evaluated more rows. A subsequent equivalence preflight isolated the issue: identical model and software settings still produced different next decoder states when the same reference step was evaluated alone or in batches of different depth. Figure~\ref{fig:equivalence-audit} shows this audit. The path to larger safe reductions is therefore specific: learned histories propose budgets, and a reference step that is unchanged by batching retains acceptance authority.

\section{Discussion}
\label{sec:discussion}

\paragraph{Phase history is a useful budget signal.}
Trace analysis, next-block prediction, and deployed LLaDA results give the same answer: previous refinement behavior helps estimate how much work the next block will need. PAG turns that signal into 4.0\% and 6.7\% fewer calls by changing only the budget. The cross-model experiments further show that history is most reliable as a guide to compute allocation, while final token decisions remain tied to current model evidence~\citep{lu2026adablock,mohamed2025sched,mohamed2026less}.

\paragraph{Block size and phase history provide different signals.}
Block size reflects both span length and AdaBlock's boundary decision, while phase history records how preceding blocks stabilized. The size-conditioned control confirms that the current block is a useful, low-cost prior. A natural next version of PAG would start from that prior and let history make a bounded adjustment, retaining PAG's ability to react to how the preceding blocks actually behaved.

\paragraph{Verification provides a path to larger gains.}
The batched pilot reduces physical calls by 14.7\% on LLaDA and 21.3\% on Dream, showing the potential of checking several proposed steps together. Realizing those gains safely requires the batched and serial transitions to produce the same tokens, cache state, attention mask, boundary, and complete next state. This batch-invariance requirement complements token-level verification in self-speculative decoders~\citep{gao2025ssd,han2026s2d2} and gives a concrete engineering target. Physical calls, evaluated rows, latency, and memory should still be reported separately.

\section{Limitations}
\label{sec:limitations}

The study covers two 7--8B model families, 256-token generations, and math/code benchmarks; it does not show that phase history is unhelpful for larger models, longer contexts, or a scheduler trained jointly with the model. CPD evidence is qualitative and detector-dependent. The statistical guarantees apply to the declared full-refinement disagreement loss and calibration mixture, not semantic correctness or arbitrary deployment data. Code-task exact-match rates are sensitive to extraction and test harnesses, so they appear in the appendix rather than drive the main claim. Latency was measured at batch size one on a single-GPU workflow and is not a serving benchmark. Finally, the batched-pilot and equivalence-preflight results diagnose this implementation of batched verification; they do not rule out verified acceleration with stricter batch-invariant kernels or serial verification.

\section{Conclusion}
\label{sec:conclusion}

PAG shows that recent refinement history can guide a diffusion language model's compute budget without retraining the model. AdaBlock chooses each block boundary from the current prediction, and PAG uses the last eight completed blocks only to set the next refinement budget. This simple division reduces LLaDA model calls by 4.0\% on GSM8K and 6.7\% on MATH-500, while accuracy is 1.60 and 1.33 percentage points lower. The size-controlled analysis identifies current block size as a useful prior, while the cross-model and output-preserving runs clarify when richer history remains useful.

The later protocols point to a practical next design: begin with a strong current-state or size-based budget, let history make a bounded adjustment, and place final token acceptance behind a batch-invariant reference check. Conservative prompt-level risk limits already preserve observed outputs while saving up to 1.24\%, and batched verification shows raw call reductions of 14.7\% and 21.3\% once exact transition matching is resolved. This architecture retains PAG's headline efficiency benefit and gives a concrete route to larger, reliable reductions.

\section{Accounting and reporting rules}

\nfe{} denotes physical invocations of the model forward function, including the initial proposal used to choose a boundary. A batched invocation counts as one physical \nfe{} and separately contributes one evaluated row per batch element. We do not translate \nfe{} reductions into floating-point operation (FLOP), energy, or latency claims. Accuracy is paired on identical prompt IDs. A run with a failed manifest, incomplete coverage, a mock record, or a failed claim gate is ineligible for a positive aggregate.

\section{Broader impact}

Reducing sequential model calls can lower latency and energy when the extra batch work does not erase the gain. It can also make generative systems cheaper to deploy at scale. The experiments expose the corresponding reliability risk: an efficiency controller that commits tokens too early can retain attractive proxy metrics while changing answers substantially. Systems using learned scheduling should therefore keep a reference fallback, audit task quality, and report batch work as well as call count. This work releases no new foundation model or scraped dataset and does not expand the underlying models' capabilities; any downstream misuse or bias remains that of the base models and their deployment context.
